# Security Team: AppSec multi-agent pipeline (Grok / xAI)

Six agents (Manager, Risk Assessor, SAST Reviewer, Pentester/DAST, Security Implementer, Crypto Specialist) audit a
backend source file and, **only after human approval**, write a hardened version to `./sandbox/`.
A live isometric 3D office shows each agent at a desk (clay-style employees), their monitor showing real pipeline data,
and a wall TV with run stats.

## Run
```bash
cp .env.example .env          # add XAI_API_KEY
cd backend && uv sync && uv run uvicorn app.main:app --reload --port 8000     # Python 3.13
cd frontend && npm install && npm run dev                                      # http://localhost:5173
```
In the UI: **Load sample** (or upload/paste code) -> **Run security agents** -> review the plan -> **Approve** or **Reject**.

## What is real vs. simplified
- Real: scan rules, route/auth analysis, approval gate, sandbox-only writes, closed-loop verification, live dashboard.
- Grok (xAI API) is used by Implementer, Crypto and (optionally) Risk. Without `XAI_API_KEY` the audit and the reject
  report still work; the write step needs the key.
- Tools are in-process (`ScopedFS`, regex/AST scanner), shaped so they can be swapped for MCP servers. No MCP servers,
  Semgrep/Trivy/ZAP, LangGraph, MongoDB or Redis are wired in yet. The Pentester only plans probes statically.
- Files marked "placeholder" match your folder tree but are not implemented. `uv.lock` / `package-lock.json` are
  generated by `uv sync` / `npm install`.
- Agent folders follow your six-agent roster (manager, risk_assessor, sast_reviewer, pentester, security_implementer,
  crypto_specialist) instead of chief/research/strategy/writer/reviewer.
